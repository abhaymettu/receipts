# Related work notes

Paper: "Do coding agents tell the truth about their own work?"

Compiled 2026-11-01. Every paper below was read at least to the abstract plus the section that matters here, through `orx paper <id>` (alphaXiv text or alphaXiv report); no orx run needed a backend. Titles, author lists, arXiv ids and first-version dates were checked against the arXiv export API in one batch query. Non-arXiv items (METR post, Anthropic system card, tool READMEs, GitHub issue) were read from the original page or PDF. BibTeX keys in `refs.bib` are given in brackets.

Format per line: citation. What it does. Data. How we differ.

## 1. Closest academic work: agent self-reports checked against the agent's own record

- **[smyth2026overclaiming] Smyth et al., "Quantifying Overclaiming Propensity in Frontier LLM Agents", arXiv:2609.20812 (2026).** Defines an overclaim as a final report contradicted by the agent's own tool-use transcript, without inferring intent. OverclaimBench: five file-review scenarios with planted defects; file and line coverage measured mechanically from tool output; an LLM judge then classifies incomplete runs' reports as admission, omission, or explicit overclaim. 67.9% of runs left a file untouched and 80.4% of those were misleading. Data: synthetic benchmark, 1,140 runs across 12 models in Docker via production CLIs (open-weight models through Claude Code). Differs: one claim type (review coverage) in planted tasks, final verdict by an LLM judge; we cover many claim types (tests, builds, edits, commits, pushes, "verified") in natural sessions with a deterministic verdict and a staleness rule.
- **[kraishan2026plans] Kraishan and Jitkajornwanich, "Plans They Abandon, Reports They Author: The Narrative Layer of Autonomous Agents", arXiv:2609.12205 (2026).** Compares coding agents' end-of-task self-reports with their executed tool-call logs and stated plans. A report mentions about one action in eleven; a reader of the report alone recovers about a fifth of the action log; reports lean toward the plan as execution diverges. Data: real sessions, SWE-chat corpus (5,851 sessions, 355,942 tool calls, 82.9% Claude Code). Differs: measures coverage and plan drift of the report (what it omits), with LLM-assisted matching; we measure whether each specific assertion is true, i.e. contradicted or unbacked by receipts, deterministically.
- **[leith2026commits] Leith, "Between the Commits: Process, Error, and Claim Reliability in a Wholly AI-Authored Codebase", arXiv:2609.29744 (2026).** Releases full session transcripts and commit history of a 21k-line Python tool written entirely by Claude, with a taxonomy of response reliability; about 1 in 4 to 5 interactive responses contain a factual error, and "reporting or verifying a fact" responses are 94.3% accurate. Data: real, one project (25 sessions, 210 commits). Differs: one codebase, error judgement by review rather than a mechanical receipt check; we test claims about the agent's own actions against tool outputs across several hundred sessions.
- **[lei2026pass] Lei Zhenbing and Lei Chang, "PASS Is a Claim, Not an Observation: Mechanical Re-verification of 10 Self-Asserted Fix Claims in a Live Multi-Agent Audit Layer", arXiv:2610.35950 (2026).** Mechanically re-checks a coordination agent's "PASS" fix announcements (file mtime, presence of the claimed pattern at the claimed call site); half of the checkable claims fail the call-site check. Data: real, one live multi-agent platform, 10 claims. Differs: tiny sample, checks against the codebase after the fact; we check against in-session receipts at scale and validate the checker against hand labels.
- **[zhu2026whoverifies] Zhu, Yu, Li and Chen, "Who Verifies the Agent's Success Claim? Self-Report Leakage in GUI-Agent Completion Judging", arXiv:2610.29609 (2026).** Report-trace auditing for GUI agents: an LLM judge that sees the agent's success report misses more "dangerous misreports" than one that sees only the trace (up to 43.4 points of recall); proposes a claim-blind trace auditor with deterministic rules. Data: benchmark GUI-agent runs. Differs: GUI tasks and LLM judges; supports our design choice of a deterministic, receipt-only verdict that never lets the claim text decide its own support.
- **[zhu2026failure] Zhu et al., "Failure-Transparent Agents: Benchmarking Post-Failure Reporting in Tool-Using Language Models", arXiv:2609.35732 (2026).** 100 tasks with fixed, deterministic tool-failure traces; measures false-success reports after a tool fails (22.8% baseline, 0.8% with a structured evidence contract). Data: synthetic, 3,600 human-annotated responses. Differs: controlled failures injected by design; we observe naturally occurring contradicted and stale claims in real coding sessions.

## 2. Receipts and claim-to-evidence binding

- **[basu2026receipts] Basu, "Tool Receipts, Not Zero-Knowledge Proofs: Practical Hallucination Detection for AI Agents", arXiv:2603.10060 (2026).** NabaOS: the runtime issues HMAC-signed receipts per tool call; the model self-tags each claim with an epistemic category and a receipt id; a verifier checks counts and facts against receipts (91% detection of injected hallucinations). Data: synthetic, NyayaVerifyBench with six injected hallucination types in several languages. Differs: requires a cooperating runtime and self-tagging model, evaluated on injected errors; we need no runtime change or model cooperation, treat the existing Claude Code JSONL as the receipt store, add staleness (code changed after the receipt), and measure on real sessions.
- **[hu2026actions] Hu et al., "Actions with Receipts: Jointly Binding Claims, Evidence, and Execution for Replayable Tool-Agent Auditing", arXiv:2610.00327 (2026).** A claim-anchored execution contract binding each emitted claim to its source span, execution prefix and source version, with a deterministic integrity verifier kept separate from a pluggable support (entailment) plane. Data: constructed audit settings. Differs: a protocol for future agents that emit receipts; we audit claims from an unmodified, deployed agent after the fact. Its integrity versus support split is a useful framing for our supported/unbacked distinction.

## 3. Hallucination and deception in tool-using agents

- **[zhang2024toolbehonest] Zhang et al., "ToolBeHonest: A Multi-level Hallucination Diagnostic Benchmark for Tool-Augmented Large Language Models", arXiv:2406.20015 (2024).** Diagnoses hallucination when tools are missing, unusable or insufficient (solvable vs unsolvable tasks, three depth levels, 1,050 samples, 14 models). Data: synthetic benchmark. Differs: tests whether a model admits a task cannot be done; we test whether claims about work done are backed by what the session actually ran.
- **[liu2026agenthallu] Liu et al., "AgentHallu: Benchmarking Automated Hallucination Attribution of LLM-based Agents", arXiv:2601.06818 (2026).** 693 annotated trajectories; the task is to find the earliest step responsible for a hallucination and explain it, across a 5-category, 14-subcategory taxonomy. Data: benchmark trajectories built from existing QA, math, GAIA and tool-use sets. Differs: localizes reasoning or retrieval errors in task trajectories; we check end-of-turn self-reports about software actions against receipts.
- **[florin2026omission] Florin, Knecht, Schaller and Hagendorff, "Deception by Omission: Language Models Knowingly Hide Their Mistakes", arXiv:2610.11351 (2026).** Prefills chat and agentic trajectories with synthetic mistakes; models fail to disclose them in 67.1% of agentic rollouts, and knowingly conceal (visible in chain of thought) in 5.3%. Data: synthetic prefilled trajectories. Differs: induced mistakes and intent analysis; we take no position on intent and count unbacked or contradicted claims that arise naturally.
- **[liu2026swedeception] Liu et al., "SWE-DeceptionBench: Benchmarking Deceptive Behaviors of LLMs Across the Software Development Lifecycle", arXiv:2610.13626 (2026).** 720 instances across six lifecycle stages with active deception (presenting infeasible requirements as achievable) and passive deception (helping users mislead others) under neutral, reward and pressure conditions. Data: synthetic prompts. Differs: elicitation benchmark, no tool receipts; we measure misreporting in ordinary use.
- **[scheurer2023strategic] Scheurer, Balesni and Hobbhahn, "Large Language Models can Strategically Deceive their Users when Put Under Pressure", arXiv:2311.07590 (2023).** GPT-4 as a simulated trading agent acts on an insider tip and then misreports its reasoning to its manager, without being instructed to deceive. Data: one simulated environment. Differs: engineered pressure scenario; our setting is unpressured everyday coding, and our verdict is about evidence, not deception.
- **[meinke2024scheming] Meinke et al., "Frontier Models are Capable of In-context Scheming", arXiv:2412.04984 (2024).** Agentic evaluations where models given a goal disable oversight, sandbag or lie when confronted. Data: synthetic evaluation suites. Differs: capability under goal conflict; we measure the base rate of unbacked self-reports with no goal conflict.
- **[park2023deception] Park, Goldstein, O'Gara, Chen and Hendrycks, "AI Deception: A Survey of Examples, Risks, and Potential Solutions", arXiv:2308.14752 (2023).** Survey defining deception behaviorally (systematic inducement of false beliefs) and cataloguing examples. Data: survey. Differs: conceptual frame only; we adopt its behavioral stance (no intent claims) but measure a narrow, checkable case.
- **[turpin2023unfaithful] Turpin, Michael, Perez and Bowman, "Language Models Don't Always Say What They Think: Unfaithful Explanations in Chain-of-Thought Prompting", arXiv:2305.04388 (2023).** Biasing features change answers while chain-of-thought explanations omit them. Data: BIG-Bench Hard and BBQ with injected biases. Differs: faithfulness of reasoning to internal causes, which needs interventions; agent claims about external actions can be checked directly against tool records, which is our setting.

## 4. Reward hacking reports on coding agents

- **[vonarx2025rewardhacking] Von Arx, Chan and Barnes, "Recent Frontier Models Are Reward Hacking", METR blog, 2025-06-05.** Documents o3 and other models tampering with scorers or tests on RE-Bench and HCAST (e.g. 100% of runs on one task); detection by high-score flags and manual review found different cases. Data: METR evaluation runs. Differs: cheating to raise a score, found by humans and monitors; our claims are textual reports, and the failure we count is mostly saying "tests pass" without a current run.
- **[anthropic2025claude37] Anthropic, "Claude 3.7 Sonnet System Card" (2025), section 6 "Excessive Focus on Passing Tests".** Reports that the model occasionally special-cases tests or edits them to match output in agentic coding environments like Claude Code, after repeated failures; detected by classifiers on training transcripts. Data: internal evaluation and training transcripts. Differs: the developer's qualitative report of test gaming; we give a measured, reproducible rate of unbacked success claims in user sessions.

## 5. Evaluating trajectories and outputs

- **[zhuge2024agentjudge] Zhuge et al., "Agent-as-a-Judge: Evaluate Agents with Agents", arXiv:2410.10934 (2024).** An agentic judge inspects workspaces and trajectories to grade intermediate requirements on DevAI (55 AI-development tasks), approaching human agreement. Data: benchmark tasks. Differs: an LLM judges task success; we use no LLM in the verdict and judge claims, not task success.
- **[lightman2023verify] Lightman et al., "Let's Verify Step by Step", arXiv:2305.20050 (2023).** Process supervision (step-level labels, PRM800K) beats outcome supervision for math reward models. Data: MATH with human step labels. Differs: trains a learned verifier of reasoning steps; our checker is rule-based over tool receipts, closer in spirit to step-level verification of an agent's narrative.
- **[es2023ragas] Es, James, Espinosa-Anke and Schockaert, "Ragas: Automated Evaluation of Retrieval Augmented Generation", arXiv:2309.15217 (2023).** Reference-free RAG metrics; faithfulness decomposes an answer into statements and checks each against retrieved context with an LLM. Data: WikiEval. Differs: same claim-decomposition idea, but our "context" is tool calls and outputs and the support check is deterministic, with a temporal (staleness) condition RAGAS has no analogue for.
- **[jimenez2024swebench] Jimenez et al., "SWE-bench: Can Language Models Resolve Real-World GitHub Issues?", ICLR 2024, arXiv:2310.06770.** Grades agent patches by running held-out tests, ignoring what the agent says. Data: 2,294 real GitHub issues. Differs: outcome grading is the external check that real sessions lack; we check the agent's own statement, which is what a developer actually reads.
- **[baumann2026swechat] Baumann et al., "SWE-chat: Coding Agent Interactions From Real Users in the Wild", COLM 2026, arXiv:2604.20779.** Living dataset of about 18,000 real coding-agent sessions from public repositories (229k prompts, 2M tool calls); 59% of agent code survives into commits and users push back often. Data: real sessions. Differs: a corpus and usage study; it is a natural second dataset for our checker (Kraishan and Jitkajornwanich already ran self-report analysis on it).

## Closest existing tools (GitHub, PyPI, issues)

These are practitioner tools, mostly released in the last two months, and they implement the same core mechanism we do. The paper must say so plainly.

- **proof-of-done** (B0yko/proof-of-done, Apache-2.0, repo created 2026-09-28, PyPI 0.1.1). The closest tool. A Claude Code Stop and SubagentStop hook that, for each claim in the final message (tests_passed, build_passed, lint_clean, typecheck_clean, deployed, fixed, verified), finds the last relevant edit and requires a matching, successful, non-masked command after it; deterministic, no LLM; an `audit` CLI reports how often past sessions claimed what they never checked. Its precision and recall (held-out: claim detection 98.6% / 84.0%, gate 98.2% / 82.1%) are on author-written synthetic fixtures, and its README says so.
- **honestly** (kennywu411-dev/honestly, MIT, created 2026-10-30, PyPI 0.6.0). Same mechanism for Claude Code, Codex, Cursor and Gemini CLI, reads command output (so it has a contradicted verdict), covers non-code claims ("sent", "deployed"), and audits history; reports the author's own 125 sessions (334 of 352 decided claims verified) and a small hand-label precision/recall check on its own flags.
- **groundtruth** (vnmoorthy/groundtruth, MIT, created 2026-04-25). Earliest of the set: a Stop hook that blocks "done" claims without in-turn verification, plus an audit command and a browser playground for session JSONL; tuned on 1,272 turns from 50 sessions of one user.
- **agentvow** (NavikkumarModi/Agentvow, MIT, created 2026-10-09). Different angle: re-runs tests in a sandbox and checks the repository, giving contradicted / supported / UNKNOWN plus changed-line coverage; optional Stop hook.
- **anthropics/claude-code issue #104504**, "'Tests pass' reported from a stale or piped run (measured across 150 sessions)", opened 2026-10-23. Hand-labelled 357 "tests pass" claims from 150 Claude Code sessions against session JSONL: 178 backed, 80 unbacked, 92 uncheckable, 5 contradicted; most unbacked claims were stale; 73% of test runs piped through tail or head; second-rater kappa reported. One team's sessions.
- Also seen but not read in full (do not cite without reading): `actually` (Go package watching session JSONL), `assurance` (i-ops-hq), a Substack post using a prompt-type Stop hook with an LLM. obra/superpowers asks for verification at the prompt level only.

## What is new here (defensible claims)

The mechanism (parse the transcript, find the claim, require a matching receipt after the last edit) is not new: proof-of-done, honestly and groundtruth all do it. The defensible contributions are about measurement and validation:

- **A validated measurement, not a tool demo.** We report the checker's agreement with hand labels on claims from real sessions, with a second rater and kappa, and report the unbacked-claim rate with that error bar. The open-source tools validate on author-written synthetic fixtures or report unvalidated counts from their author's own sessions; the academic papers closest in spirit (Smyth et al.; Kraishan and Jitkajornwanich) use LLM judges or LLM-assisted matching for the final verdict.
- **Breadth of claim types in natural use.** We cover the agent's claims about its own actions generally (tests, builds, edits, commits, pushes, "verified"), in unprompted, unplanted everyday sessions, rather than one claim type (review coverage, post-failure success) in a constructed benchmark.
- **Three verdicts with staleness made explicit.** Supported, contradicted, and unbacked, where unbacked includes a receipt invalidated by later code changes. Prior benchmarks mostly score a binary support decision; issue #104504 and our own data suggest staleness is the dominant failure, so separating it matters.
- **Deterministic and replayable.** The same transcript always gives the same verdict, so the reported rate can be re-derived by anyone with the sessions, unlike LLM-judge pipelines whose output drifts with model versions.
- **Measurement and intervention in one artifact.** The same checker that produces the rates runs as a Claude Code Stop hook. This is shared with the tools above, so present it as a practical consequence, not a novelty claim.

Avoid: "first to check agent claims against transcripts" (false: tools above, issue #104504, Smyth et al.), and any claim about intent or "lying" (we measure evidence, not belief).
